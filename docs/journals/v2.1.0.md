## Top-3 Lessons Learned

### 1. Subagent Compression Continues to Scale

Parallel wave execution (W1: P01‖P02‖P06‖P09 / W2: P03‖P04‖P08 / W3: P05‖P07‖P10)
cut critical-path from 24.5d sequential → ~22d wall-clock. File-ownership isolation
(each subagent owns exclusive glob patterns) eliminated merge conflicts entirely in 12 phases.
Compression ratio improved vs v2.0: average phase turnaround 1.9d vs 2.4d in v2.0 P-phases.
**Action:** maintain file-ownership-first design in v2.2 plan; assign glob boundaries before
spawning, not after.

### 2. Fresh-Prompt Protocol Still Works at Scale

Zero anti-trace hits across 152 v2.1 files confirms the per-subagent fresh-prompt protocol
(no carry-over of prior session context; explicit anti-trace grep gate per phase) scales to
multi-wave parallel execution. Each subagent received only its phase file + relevant codebase
snapshot — no accumulation of cross-phase context. This prevented "context bleed" that caused
one anti-trace near-miss in v2.0 W3.
**Action:** maintain mandatory anti-trace grep gate in phase acceptance criteria for v2.2.

### 3. Schema Delta Deferred-Merge Pattern Works for Parallel Waves

P01 (provider_settings table) and P03 (material_images table) ran in parallel waves W1/W2
without schema conflicts because migration numbering was pre-assigned in P00 (0005-0011 locked).
Each subagent wrote its own migration file; P12 verified sequence integrity at release.
In v2.0 we had one schema collision between P03 and P05 that required a reconciliation pass.
Pre-locking migration numbers in P00 eliminated this entirely.
**Action:** always pre-assign migration numbers in P00/architecture phase for v2.2.

## Top-3 Open Issues for v2.2

### 1. BullMQ Workers Wiring Smoke (Deferred Validate)

MCP token → Claude Desktop integration marked as "Day-2 validate" in P12 (not blocking release tag).
BullMQ vision queue workers need smoke validation with a live Docker stack + actual PDF upload.
The unit + integration tests cover worker logic but not end-to-end queue → worker → DB write.
**Priority:** High — blocks verifying vision caption UX in production.

### 2. Full Mobile UX (Deferred v2.2)

Three-panel wiki browser ships with desktop-first layout. Mobile breakpoints are stubbed but
not polished. axe-core CI check is wired but thresholds not enforced (observability only in v2.1).
Full responsive pass + axe-core CI gate with failure threshold = v2.2 scope.
**Priority:** Medium — affects end-user adoption on tablet/mobile.

### 3. Audit Log Viewer Admin UI (Deferred v2.2)

Audit events are written (actor_email_hmac, action, resource, timestamp) and cleanup cron
runs at 12-month retention. But there is no admin UI to browse/filter audit events.
Compliance reviewers currently need direct DB access. A simple paginated audit log viewer
(filter by actor / resource / date range) is the most-requested missing admin feature.
**Priority:** Medium — compliance ask; workaround via direct DB query documented in operations.md.
