## What Shipped

`wiki-memory` — optional capture-only skill that harvests Claude Code session transcripts via 3 hooks (SessionStart, PreCompact, SessionEnd) using pure bash + jq. Zero Python, zero SDK dependencies.

**Artifacts**:
- Slash commands: `/wiki-memory enable|disable|status|flush|logs`
- Schema v2: `raw/sessions/` (raw transcripts), `wiki/qa/` (specialized 9-field frontmatter), `.state.json` (sha256-based incremental ingest tracking), `.memory.log` (audit trail)
- 4 extended skills: `wiki-query --save` writes to `wiki/qa/`, `wiki-ingest` with hash-skip + `--promote-qa` mode, `wiki-lint` with 6 new audits, `wiki` wizard Q11 cascade for memory toggle
- Off by default; pure opt-in via wizard or slash command

---

## Why It Matters

Closed the "session knowledge loss" gap — every Claude Code session now *can* be captured and ingested into the wiki graph without manual transcript hunting. The hook-based approach means capture happens asynchronously, never blocking user workflows. By deferring auto-compile to v1.2 (see below), v1.1.0 stays lean and verifiable.

## Critical Technical Decisions

### 1. Capture-Only, No Auto-Compile (Red-team C-1)
**Decision**: Removed native auto-compile (SessionEnd → spawn claude-cli to ingest). Blocked due to:
- **Recursion risk**: SessionEnd hook spawning claude-cli could itself trigger SessionEnd hook
- **Cost runaway**: Unmetered recursive ingestion across user's fleet
- **Complexity**: File-locking, worker queues, deduplication all needed

**Deferred to v1.2** with proper worker process + file-locking. v1.1.0 user runs `/wiki-ingest` manually.  
**Rationale**: Ship verifiable, testable core; add orchestration with guardrails later.

### 2. PreCompact Exit-Code Discipline
**Decision**: PreCompact hook must exit 0 always; all user-facing logic wrapped in `( ... ) || true; exit 0`.  
**Why**: PreCompact exit ≠ 0 **blocks user's session compaction**. Any unhandled error (mkdir failure, jq parse) would lock user out of normal workflow.  
**Guard**: SessionStart with `source: compact` skips injection to avoid double-context when user manually triggers compaction.

### 3. Self-Disable Hook Check (Red-team Q8/Q9)
**Implementation**: Every hook script line 2: `[[ -f "$(dirname "$0")/../SKILL.md" ]] || exit 0`  
**Closes**: Orphan-hooks failure mode if user uninstalls skill without disabling hooks in `.claude/hooks/` first.  
**Cost**: Single stat per hook invocation; negligible impact.

### 4. mkdir-Based Atomic Lock (macOS 3.2 Compatibility)
**Problem**: Standard `flock` unavailable in bash 3.2 (macOS default).  
**Solution**: Portable concurrent-write protection via `mkdir` atomicity.  
**Trade-off**: Slightly slower than flock; adequate for infrequent session captures.

### 5. Status.sh Auto-Discovery (Post-Release Patch 667a5bb)
**Found during smoke test**: Running `/wiki-memory status` from vault subdirectory reported "not configured" even though wiki was active in parent directory.  
**Root cause**: Status only checked `$PWD`, not parent chain.  
**Fix**: Walk up from `$PWD` to find `.claude/wiki-memory.conf`, stop at `/` or `$HOME`.  
**Lesson**: Hook behavior scripts need defensive cwd handling; pwd assumptions fail in subdirectory invocations.

## Gotchas for Future Me

1. **Hook removal ceremony**: If user uninstalls wiki-memory, they must run `/wiki-memory disable` first to remove hooks from `.claude/hooks/`. Document this; consider auto-cleanup on skill uninstall.

2. **qa Frontmatter is strict**: 9 required fields (question, answer, context, category, keywords, confidence, source, date, version). Missing any one fails ingest validation. If ingesting old Q&A, promote-qa must backfill missing fields.

3. **SHA256 state drift**: `.state.json` tracks ingest history by transcript SHA256. If transcript file gets edited post-capture, re-ingest creates duplicate entry. Consider tombstone mechanism or incremental hash for production use.

4. **PreCompact exit 0 contract**: Tempting to surface errors via exit codes. Don't. Any failure blocks compaction and confuses users. Return errors via log-only (`.memory.log`, read via `/wiki-memory logs`).

5. **Karpathy lineage, not genealogy**: This work extends the LLM Wiki pattern (structured session→concept graphs) but shares zero code/commit lineage with prior approaches. Anti-trace audit clean.
