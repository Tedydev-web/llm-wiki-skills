## Lessons Learned

### 1. F3 Spike Methodology — verify before implementing

The pre-impl spike for Layer-2 recursion guard (does `claude -p` propagate env-vars to its subprocess?) saved significant rework. Pattern: when a safeguard depends on undocumented platform behavior, spike it before writing production code. Bonus discovery: `claude -p` requires `--settings <file>` for config — not documented, found only by running the spike.

### 2. 7-Day Grace Period Decision

Initial lean was 1 hour for legacy sidecar migration. Validation raised it to 7 days (vacation-safe). The cost: slightly more code for grace-period tracking. The benefit: users who go on vacation and return with a v1.2 upgrade won't lose vault config silently. Lesson: grace periods for user-facing migrations should be measured in days, not hours.

### 3. Cost-Cap Recovery UX — refuse + log + manual rm

When cost-cap counter is corrupt, the system refuses to run (never silently zero the counter). Users must manually `rm ~/.config/wiki/cost-cap.state`. This is inconvenient but prevents cost runaway from corruption. Lesson: for financial controls, prefer loud failure over silent recovery. The operator (user) should be informed and choose recovery, not the system.

### 4. Anti-Trace Meta-Reference Paradox (F14)

The ADR documenting the anti-trace contract contains the forbidden tokens (to describe what they are). A naive grep would flag the docs/decisions/ directory. Fix: canonical test script auto-excludes `docs/` from the grep scope. Lesson: test scripts that check for forbidden patterns need exclusion lists for self-referential documentation. The exclusion list itself must be audited (it's not excluded from exclusion audit).

### 5. enable-hooks.sh Double-rmdir Bug

`release_lockdir` rmdir's the lock, then the EXIT trap also tries to rmdir it (already gone → exit 1). Under `set -e`, this exits the script with code 1 even though all work succeeded. Fix: the trap should guard with `[[ -d "$lock" ]]` before rmdir. Not fixed in v1.2.0 (would touch P04-owned file post-freeze); tracked for v1.2.1 patch.

### 6. Step Numbering — Step 16 Already Existed

Phase plan assumed a gap at Step 16 (planner thought steps went 1-15 then 17). Actual: Step 16 was created by P02 for `_schema` version audit (step 14c promoted). Step 17 (memory-log) is correctly numbered 17. The renumbering task (Task 2) was correctly skipped to avoid collision. Lesson: always check actual file state before cosmetic renumbering.
