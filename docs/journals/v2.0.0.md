## Top-3 lessons learned

### 1. Subagent compression works at scale — with disciplined file ownership

Running parallel subagents for disjoint phases (P00‖P01, P03‖P04, P06‖P07, P09‖P10‖P11) compressed ~51 sequential days into ~8h wall-time. The critical enabler was the file ownership map in `plan.md` — without explicit write-boundary declarations, parallel agents would have produced merge conflicts. The discipline of "each agent owns distinct file trees" scaled cleanly to 13 phases.

**For future plans:** Author the file ownership map before spawning any parallel agents. It is the most load-bearing artifact in the plan, more important than the phase descriptions themselves.

### 2. Fresh-prompt protocol works — and is worth the overhead

The wiki-compile system prompt (`apps/wiki-team/jobs/wiki-compile/prompts/v1.md`) and MCP system instructions were both authored by a fresh-context subagent given only ADR 010+012 as input — no access to upstream source. The user review gate confirmed zero pattern-match to upstream prompt prose. The SHA-256 hash pin in the P11 prompt regression test locks the result going forward.

**For future LLM-adjacent products:** Treat system prompts as first-class IP artifacts. Fresh-context authoring + hash-pinned regression test + user review gate is a reproducible protocol that prevents the most serious derivative-work risk.

### 3. Anti-trace as a committed gate prevented several near-misses

The anti-trace CI check (`anti-trace.yml`) ran on every commit to `feat/v2-team-mode`. On at least 3 occasions during P06 and P07 authoring, an agent produced a constant name or function name that substring-matched a forbidden token. The gate caught these before they reached review. Without the committed gate (not just a manual checklist), at least one would have slipped through.

**For future derivative work:** Wire the anti-trace check into CI before writing the first line of code, not after. The script needs to exist and run clean from day 0.

## Top-3 open items for v2.1

### 1. Extended TypeScript bridge path (team-bridge v2)

P10 shipped docs-only (zero-code) bridge: users wire `wkt_` token via Claude Desktop JSON config. The plan called for an optional TypeScript extension that would let the personal wiki skills call team APIs directly (workspace listing, semantic search passthrough). Deferred because docs-only path covers 90% of use cases at v2.0 launch.

**v2.1 scope:** `apps/wiki-skills/integrations/team-bridge/team-bridge-client.ts` — typed Hono client wrapper; `wiki-query --team` flag to federate search across local vault + team workspace.

### 2. Full SSE transport for MCP (legacy client support)

P07 ships Streamable HTTP as primary transport (current MCP spec). The SSE legacy transport returns 501 with a clear error. Some clients (older Claude Desktop builds, third-party MCP clients) require SSE. Deferred per ADR 012 because the 501 stub is safe and forces clients to upgrade.

**v2.1 scope:** Implement full SSE transport in `apps/wiki-team/mcp-host/`. No new tool surface needed — same 8 tools, second transport.

### 3. Single-binary release target (Bun compile)

`bun build --compile` can produce a standalone binary for `apps/wiki-team/server.ts`. The AGPL boundary makes this non-trivial: distributing a binary with MuPDF.js bundled requires AGPL-compliant source distribution. The path is documented in ADR 009 as experimental and the Docker Compose path is the supported default.

**v2.1 scope:** Produce a binary artifact in CI without `packages/wiki-pdf-extract/` bundled (PDF extraction becomes opt-in sidecar via CLI flag). Measure binary size + cold-start time. Gate on user demand signal.

## Crown jewels shipped in v2.0

**Dual-realm RBAC engine (P05):** Pure-function `evaluatePolicy` with `compileScopeFilter` returning typed Drizzle SQL fragments. 28 contract tests. No N+1 policy checks at query time. The design separates policy evaluation from query execution cleanly — the pattern is reusable for any multi-tenant TS product.

**Wiki-compile agent loop (P06):** `STEP_BUDGET=30` BullMQ worker with 7 tools, idempotency triple-key, daily cost cap via Redis INCR, and recursion guard. The fresh-authored system prompt (clean-room protocol) is hash-pinned. This is the core value-add over v1.2 personal mode: automated multi-document synthesis with cross-links.

**8-tool MCP surface (P07):** Every tool is RBAC-gated via `evaluatePolicy` + `compileScopeFilter`. Bearer redacted from error context. Dual-transport with safe 501 fallback. `directory.lookup` admin-gated. This surface makes the team wiki directly queryable from Claude Desktop without any custom integration code — users just configure a Bearer token.
